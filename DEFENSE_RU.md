## Task 1. Валидация формы — Contact

Файлы: `contact.html` и первый раздел `js/site.js`.

1. В HTML у полей есть `required`, у email — `type="email"`, у пароля — `minlength="8"`. Поле подтверждения содержит `data-match="password"`.
2. `setupValidation()` получает форму, элемент результата, правила и сообщение успеха. Объекты `contactRules` и `subscriptionRules` содержат список обязательных полей и правила в JavaScript. При каждой отправке `validationField()` заново ищет каждое поле в форме: отсутствие, дубликат или отключённое поле блокируют успех. Удаление HTML-атрибута `required` не отменяет проверку.
3. Обработчик `submit` вызывает `event.preventDefault()`, чтобы страница не перезагружалась и статический сайт не отправлял форму.
4. `fieldError(field, rule, form, rules)` возвращает текст ошибки или пустую строку. `trim()` выявляет пустые значения и строки из пробелов. Формат email проверяется регулярным выражением по правилу JavaScript, даже если удалить `type="email"`. Это проверка формата, не существования адреса.
5. Длину сравниваем с `rule.minLength` (8), а подтверждение — со значением исходного пароля по `rule.match`. Удаление HTML-атрибутов `minlength` и `data-match` не отключает эти проверки. Сам пароль не обрезаем: пробелы могут быть частью пароля, но пароль только из пробелов отклоняем.
6. `showFieldError()` записывает ошибку через `textContent`, добавляет класс `is-invalid` и `aria-invalid`. `aria-describedby` связывает поле с ошибкой.
7. Фокус переходит на первую ошибку. При вводе исправленные ошибки исчезают; изменение исходного пароля повторно проверяет подтверждение. `reset` убирает сообщения. При успехе пароли очищаются.

Показать: отправить пустую форму; ввести неправильный email, пароль `short` и другое подтверждение; затем заполнить всё корректно, например email `student@example.com`, пароль и подтверждение `CampusDemo26`; нажать Check message и затем Clear Form. Это вымышленные демонстрационные данные.

Важно: `novalidate` отключает стандартные всплывающие сообщения браузера, чтобы показать собственные. Оно не отключает наш JS. Форма учебная, аккаунт и подписка не создаются. В реальном приложении сервер тоже обязан проверять данные.

## Task 2. Accordion — Resources

В HTML вопросы — настоящие `<button>`, ответы изначально имеют `hidden`. `aria-controls` хранит `id` ответа, `aria-expanded` — состояние вопроса.

При `click` находим ответ через `getElementById()`. Из `aria-expanded` узнаём, нужно раскрыть или закрыть ответ. Снимаем `hidden`, а `Element.animate()` меняет высоту и прозрачность за 240ms. После закрытия снова ставим `hidden`. `inert` исключает ссылки закрываемого ответа из фокуса. Если пользователь просит уменьшить движение, переключение выполняется сразу.

Показать: все ответы сначала скрыты; нажать вопрос дважды. Клавиши Enter и Space также работают, потому что это button. Несколько ответов могут быть раскрыты одновременно — задание это допускает.

## Task 4. Смена фона — Home

Массив `backgrounds` содержит четыре объекта с названием и цветом. Переменная `backgroundIndex` хранит текущий индекс. При нажатии:

```js
backgroundIndex = (backgroundIndex + 1) % backgrounds.length;
document.body.style.backgroundColor = backgrounds[backgroundIndex].color;
```

Оператор `%` — остаток от деления: после последнего индекса снова получаем ноль. CSS `transition` делает смену плавной. Цвета светлые, чтобы текст оставался читаемым. После перезагрузки начальный цвет восстанавливается; localStorage здесь не используется.

## Task 5. Дата и время — Home

`new Date()` получает текущее время устройства. `Intl.DateTimeFormat('en-US', options)` показывает месяц словами и время с секундами. Текст записывается в `<time>` через `textContent`, а машинное значение — в `dateTime` как ISO-строка из `toISOString()`.

`updateClock()` вызывается сразу; `setInterval(updateClock, 1000)` повторяет вызов примерно раз в секунду. Каждый вызов создаёт новый Date, поэтому мы не накапливаем ошибку, вручную прибавляя секунды. Отображается часовой пояс устройства; в скриншотах — Asia/Almaty. В фоновой вкладке браузер может замедлять таймер.

## Почему один JS-файл работает на четырёх страницах

Внизу каждой страницы:

```html
<script src="vendor/bootstrap/bootstrap.bundle.min.js" defer></script>
<script src="js/site.js" defer></script>
```

Пути относительные, поэтому работают и локально, и в подпапке GitHub Pages. `defer` выполняет скрипт после разбора HTML. `querySelector()` возвращает null, если компонента нет; проверки `if (clock)` и `if (!form || !status) return` не дают обращаться к отсутствующим элементам. Bootstrap отвечает за navbar/carousel, наш файл — за пять заданий.

## Частые вопросы преподавателя

- DOM — представление HTML как дерева объектов, с которыми работает JavaScript.
- `querySelector` находит первый элемент; `querySelectorAll` — коллекцию. `forEach` обрабатывает каждый найденный элемент.
- `addEventListener` связывает событие с функцией; функция выполняется после события, а не при подключении слушателя.
- `const` — переменная, которую не переназначаем; `let` — значение, которое меняется, например индекс цвета.
- `textContent` выводит текст; `innerHTML` разбирает HTML. Для сообщений используем `textContent`.
- `===` сравнивает без преобразования типов. Атрибуты читаются строками, поэтому сравниваем с `'true'`.
- В чём отличие HTML/CSS/JS: структура / оформление / поведение.
- Почему нужна серверная проверка: клиентский код можно изменить или обойти; здесь демонстрация frontend без backend.
- Почему часы могут отличаться на разных компьютерах: используются настройки времени и часового пояса устройства.
